# 39. TEST VE SİMÜLASYON AYRIMI

TEST YAPMAK SERBESTTİR.

ANCAK TEST İLE UYGULAMANIN GERÇEK İŞLEYİŞİNİ SAHTELEMEK FARKLI ŞEYLERDİR.

Örneğin:

DOĞRU:

Gerçek ödeme hesaplama fonksiyonunu unit test ile test etmek.

DOĞRU:

DOĞRU:

Gerçek business logic üzerinden E2E test çalıştırmak.

DOĞRU:

Yazıcı entegrasyonunu gerçek bağlantı olmadan test etmek için ayrı bir test adapter/mock katmanı kullanmak.

YANLIŞ:

Production koduna:

if (demoMode) {
return true;
}

gibi bypass eklemek.

YANLIŞ:

Database'den veri gelmediğinde:

return demoCustomers;

yapmak.

YANLIŞ:

return fakeSuccessfulResponse;

yapmak.

YANLIŞ:

Butona basıldığında gerçek işlem yapılmadan:

toast("Başarılı");

göstermek.

# 40. MOCK KULLANILMASI GEREKEN DURUMLAR

Test altyapısında mock/stub/fake kullanılması gerekiyorsa bu mekanizma:

* production kodundan izole edilmeli
* açıkça test ortamına ait olmalı
* production build'e yanlışlıkla dahil olmamalı
* gerçek business logic'i bypass etmemeli
* gerçek uygulamanın çalışıyor gibi görünmesini sağlamamalı

Örneğin fiziksel yazıcı olmadan yazıcı test ediliyorsa:

TEST ORTAMI:
Mock Printer Adapter

PRODUCTION:
Gerçek Printer Adapter

şeklinde ayrıştır.

Ancak production uygulamasında:

"Yazıcı bağlı değil ama yazdırıldı."

gibi bir davranış kesinlikle oluşturma.
